# SO-ELL: which ebook practice lines up with midterm scores?

Michigan Data Science Team project on Runestone interactive-ebook logs from the intermediate Python course (SI 206 / SI 201): 19.8M events, 8 semesters, 1,397 students, 2,745 midterm scores rebuilt from the logs.

**Findings** (all within semester × midterm cohorts; associations, not causal effects):

- Students in the top quarter of **first-try Parsons success** score about **20 points higher** on the midterm than the bottom quarter of the same cohort (95% CI 18.8–22.1). The gap holds with effort controls, with the student's own midterm 1 score held fixed, and under every answer-key scoring threshold tried.
- **How much** a student practices matters far less than **how well** their first attempts go.
- An at-risk model (bottom quarter of the cohort), tested on semesters it never saw, reaches **AUC 0.78**. Two weeks before the exam it still reaches **0.71**.

Full write-up: **[docs/design_report.pdf](docs/design_report.pdf)**. It covers design choices, data problems found and fixed, methods, limitations, and a runbook.

## See how it was built

The raw logs are student data shared with us by the course for this project, so **they are not in this repository**. Instead, every result was produced by running these notebooks in order. Each one prints the source of every function and SQL file just before it runs, then shows the aggregate result:

| Notebook | Stage |
|---|---|
| [01_ingest](notebooks/01_ingest.ipynb) | checksummed raw exports → one event log; why student ids needed namespacing |
| [02_exam_windows](notebooks/02_exam_windows.ipynb) | which timed exam is the real midterm, and each student's window |
| [03_scoring](notebooks/03_scoring.ipynb) | rebuilding midterm scores from in-exam answers |
| [04_features](notebooks/04_features.ipynb) | leakage-guarded pre-exam practice features (pandas + DuckDB SQL) |
| [05_analysis](notebooks/05_analysis.ipynb) | feature screening with FDR, bootstrap, fixed effects, sensitivity |
| [06_models](notebooks/06_models.ipynb) | at-risk models, leave-one-semester-out, lead time, MLflow |
| [07_report](notebooks/07_report.ipynb) | practice exams, cramming, every figure |

## Layout

```
src/so_ell/     the pipeline as a tested package (one module per stage)
sql/            DuckDB feature queries
notebooks/      executed build walkthrough (generated by build_notebooks.py)
tests/          unit tests + a synthetic end-to-end test that runs without the real data
app/            Streamlit dashboard over outputs/
outputs/        aggregate tables, figures, Looker Studio CSVs, data-quality reports
data/raw/       MANIFEST.csv only (file list + SHA-256); exports stay local
docs/           design report, feature dictionary
```

## Run it

Requires [uv](https://docs.astral.sh/uv/) and the raw exports in `data/raw/` (see [data/raw/README.md](data/raw/README.md)).

```bash
uv sync --all-extras
make test          # no data needed: unit tests + synthetic end-to-end pipeline
make notebooks     # full pipeline through notebooks 01-07 (~8 GB RAM)
uv run so-ell all  # same stages, headless; `--from <stage>` to resume
make app           # Streamlit dashboard
make mlflow        # model runs
make dagster       # the pipeline as Dagster assets
make pdf           # rebuild docs/design_report.pdf
```

Stack: Python 3.13, uv, DuckDB, pandas, Pandera, statsmodels, scikit-learn, MLflow, Dagster, Jupyter, Streamlit, pytest, ruff, GitHub Actions.
